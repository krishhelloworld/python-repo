Tokenization

Tokenization splits raw text into individual units called tokens — words, subwords, or sentences. It is always the first step in any NLP pipeline. No model can process raw strings; everything must be tokenized first.

Input
"Hello World"
Raw string
Output
["Hello","World"]
List of tokens
Library
NLTK
word_tokenize
Types
3
Word · Sentence · Subword
Real-world applications
🔍
Google Search
Tokenizes your query to match against indexed documents word-by-word.
📧
Gmail Spam Filter
Tokenizes emails before checking each word against spam patterns.
🤖
ChatGPT / Claude
Every LLM tokenizes input using BPE (Byte-Pair Encoding) before processing.
📱
Autocorrect
Splits text into words to detect and correct misspellings individually.
01_tokenization.pyPython + NLTK
import nltk
from nltk.tokenize import (
    word_tokenize,       # splits into words + punctuation
    sent_tokenize,       # splits into sentences
    TreebankWordTokenizer,
    TweetTokenizer       # handles @mentions, #hashtags, emojis
)

text = "Hello! My name is Ravi. I am studying NLP at AKTU. It's amazing!"

# --- 1. Word Tokenization ---
word_tokens = word_tokenize(text)
print("Word tokens:", word_tokens)
# ['Hello', '!', 'My', 'name', 'is', 'Ravi', '.', ...]

# --- 2. Sentence Tokenization ---
sent_tokens = sent_tokenize(text)
print("\nSentence tokens:", sent_tokens)
# ['Hello! My name is Ravi.', 'I am studying NLP at AKTU.', "It's amazing!"]

# --- 3. Tweet Tokenizer (for social media) ---
tweet = "I LOVE NLP 😍 @Google #MachineLearning isn't it great??"
tweet_tok = TweetTokenizer()
print("\nTweet tokens:", tweet_tok.tokenize(tweet))
# ['I', 'LOVE', 'NLP', '😍', '@Google', '#MachineLearning', "isn't", 'it', 'great', '?', '?']

# --- 4. Token count statistics ---
print(f"\nTotal words: {len(word_tokens)}")
print(f"Unique words: {len(set(word_tokens))}")
print(f"Total sentences: {len(sent_tokens)}")

Stemming

Stemming reduces words to their root form by chopping off suffixes using rules (not a dictionary). Fast but crude — "running" → "run", but "studies" → "studi". Used when speed matters more than accuracy.

Input
"running"
Inflected word
Output
"run"
Stem (root)
Speed
Fast
Rule-based, no dict
Accuracy
~70%
May produce non-words
🔍
Search Engines
Early Google used stemming so "run", "running", "ran" all match the same documents.
📰
Information Retrieval
Reduces index size by collapsing word variants to one stem.
📊
Text Mining
Reduces vocabulary before clustering documents by topic.
⚡
Real-time Systems
Preferred over lemmatization when speed is critical (streaming data).
02_stemming.pyPython + NLTK
from nltk.stem import PorterStemmer, SnowballStemmer, LancasterStemmer
from nltk.tokenize import word_tokenize

# --- Three popular stemmers ---
porter    = PorterStemmer()      # Most popular, balanced
snowball  = SnowballStemmer("english")  # Improved Porter
lancaster = LancasterStemmer()   # Most aggressive

words = ["running", "runs", "ran", "easily", "fairly",
         "studies", "studying", "studied", "happiness",
         "playing", "played", "beautiful"]

print(f"{'Word':<15} {'Porter':<12} {'Snowball':<12} {'Lancaster'}")
print("-" * 55)
for word in words:
    p = porter.stem(word)
    s = snowball.stem(word)
    l = lancaster.stem(word)
    print(f"{word:<15} {p:<12} {s:<12} {l}")

# --- Practical: stem an entire sentence ---
sentence = "The students are studying NLP and building amazing applications"
tokens = word_tokenize(sentence.lower())
stemmed = [porter.stem(token) for token in tokens]
print(f"\nOriginal : {tokens}")
print(f"Stemmed  : {stemmed}")

Lemmatization

Lemmatization uses a vocabulary and grammar rules (WordNet) to return the dictionary base form (lemma). Slower than stemming but always produces a real word. "studies" → "study", "was" → "be", "better" → "good".

Input
"studies"
Inflected word
"study"
Real dictionary word
Library
NLTK / spaCy
WordNetLemmatizer
Accuracy
~95%
Uses WordNet dict
💬
Chatbots (Google Assistant)
Lemmatizes user input to understand "ran", "running", "runs" all as the same intent "run".
📚
Question Answering
Matches question tokens to document tokens regardless of tense or form.
🔬
Medical NLP
Normalizes clinical notes — "administered", "administering" → "administer".
📖
Spell Checker
Checks if the lemma exists in the dictionary to validate word forms.
03_lemmatization.pyPython + NLTK + spaCy
import nltk
from nltk.stem import WordNetLemmatizer
from nltk.corpus import wordnet
import spacy

# --- Method 1: NLTK WordNetLemmatizer ---
lemmatizer = WordNetLemmatizer()

# IMPORTANT: you must specify POS tag for accuracy
# 'v' = verb, 'n' = noun, 'a' = adjective, 'r' = adverb
words_pos = [
    ("studies",  "v"), ("running", "v"), ("better",   "a"),
    ("was",      "v"), ("children","n"), ("happily",  "r"),
    ("playing",  "v"), ("geese",   "n"), ("best",     "a"),
]

print(f"{'Word':<12} {'POS':<6} {'Lemma'}")
print("-" * 35)
for word, pos in words_pos:
    lemma = lemmatizer.lemmatize(word, pos=pos)
    print(f"{word:<12} {pos:<6} {lemma}")

# --- Method 2: spaCy (automatically detects POS) ---
nlp = spacy.load("en_core_web_sm")
text = "The children were playing with their geese and running happily"
doc = nlp(text)

print("\n--- spaCy Auto-Lemmatization ---")
for token in doc:
    print(f"{token.text:<15} → {token.lemma_:<15} [{token.pos_}]")

Stopwords Removal

Stopwords are common words (the, is, a, and, in…) that carry little meaning for most NLP tasks. Removing them reduces noise, shrinks vocabulary size, and speeds up training. NLTK has 179 English stopwords built-in.

NLTK English Stopwords
179
Words to filter
Vocab Reduction
~30–50%
Smaller feature space
When to SKIP
Sentiment
"not good" → "good" is wrong!
04_stopwords.pyPython + NLTK
from nltk.corpus import stopwords
from nltk.tokenize import word_tokenize

# --- Load stopwords ---
stop_words = set(stopwords.words('english'))
print(f"Total English stopwords: {len(stop_words)}")
print("Sample:", list(stop_words)[:15])

# --- Filter a sentence ---
text = "The food at the restaurant was not good and I did not enjoy it at all"
tokens = word_tokenize(text.lower())

# Without stopword removal
print(f"\nOriginal ({len(tokens)} tokens):", tokens)

# With stopword removal
filtered = [w for w in tokens if w not in stop_words]
print(f"Filtered ({len(filtered)} tokens):", filtered)

# --- Custom stopwords (add domain-specific) ---
custom_stop = stop_words | {"also", "however", "therefore", "moreover"}

# --- ⚠️ WARNING: negation problem ---
negative_text = "The food was NOT good and NOT tasty"
neg_tokens = word_tokenize(negative_text.lower())
bad_filter = [w for w in neg_tokens if w not in stop_words]
print(f"\n⚠️  Negation problem: {bad_filter}")
# "not" is a stopword! "NOT good" becomes just "good" → wrong sentiment!

# --- FIX: keep negation words ---
keep_negation = stop_words - {"not", "no", "nor", "never", "neither", "n't"}
good_filter = [w for w in neg_tokens if w not in keep_negation]
print(f"✓  Fixed (keep 'not'): {good_filter}")

Original (17 tokens): ['the', 'food', 'at', 'the', 'restaurant', 'was', 'not', 'good', 'and', 'i', 'did', 'not', 'enjoy', 'it', 'at', 'all']

Parts of Speech (POS) Tagging

POS tagging assigns each word a grammatical role: Noun, Verb, Adjective, Adverb, etc. This is critical for understanding sentence structure, enabling correct lemmatization, and is the foundation of all advanced NLP tasks like NER and parsing.

Common Tags
NN/VB/JJ
Noun·Verb·Adjective
NLTK Tagset
45
Penn Treebank tags
spaCy Tagset
18
Universal POS tags
📝
Grammar Checker
Grammarly uses POS to detect subject-verb agreement errors ("He run" → should be "runs").
🔄
Machine Translation
Google Translate needs POS to reorder words correctly between languages.
🎤
Text-to-Speech
Siri/Alexa uses POS to stress the right syllables (the noun "REcord" vs verb "reCORD").

import nltk
import spacy
from nltk.tokenize import word_tokenize

sentence = "Google was founded in California by Larry Page in 1998"

# --- Method 1: NLTK POS Tagging ---
tokens = word_tokenize(sentence)
nltk_pos = nltk.pos_tag(tokens)
print("NLTK POS Tags:")
for word, tag in nltk_pos:
    print(f"  {word:<15} → {tag}")

# --- Common Penn Treebank Tags ---
tag_meanings = {
    'NN': 'Noun (singular)',    'NNP': 'Proper Noun',
    'VBD': 'Verb (past tense)', 'VBN': 'Verb (past participle)',
    'JJ': 'Adjective',          'RB': 'Adverb',
    'IN': 'Preposition',        'DT': 'Determiner (the/a)',
    'CD': 'Cardinal number',    'PRP': 'Personal pronoun',
}

# --- Method 2: spaCy (richer, more accurate) ---
nlp = spacy.load("en_core_web_sm")

print("\nspaCy POS Tags:")
for token in doc:
    print(f"  {token.text:<15} POS={token.pos_:<8} Tag={token.tag_:<6} Dep={token.dep_}")

# --- Extract only nouns ---
nouns = [token.text for token in doc if token.pos_ == "NOUN"]

print(f"\nNouns: {nouns}")
print(f"Verbs: {verbs}")

One Hot Encoding (OHE)

One Hot Encoding converts each word into a binary vector of size equal to the vocabulary. Only one position is 1 (hot) — the rest are 0. Simple to understand, but creates huge sparse vectors and has no semantic meaning.

Vector Size
= Vocab
One position per word
Sparsity
Extreme
Only 1 bit is 1
Semantic Info
None
cat ≠ dog equally
Visual: Vocabulary of 5 words → OHE vectors
Vocab: [ good, bad, pizza, burger, food ] idx:0 idx:1 idx:2 idx:3 idx:4 "good" → [ 1, 0, 0, 0, 0 ] "bad" → [ 0, 1, 0, 0, 0 ] "pizza" → [ 0, 0, 1, 0, 0 ] "burger" → [ 0, 0, 0, 1, 0 ] "food" → [ 0, 0, 0, 0, 1 ] Problem: cos_similarity("cat", "kitten") = 0 ← no semantic similarity!
07_one_hot_encoding.pyPython + NumPy + sklearn
import numpy as np
from sklearn.preprocessing import LabelEncoder, OneHotEncoder

# --- Manual OHE from scratch ---
corpus = ["The food is good", "The food is bad", "Pizza is amazing", "Burger is bad"]
all_words = sorted(set(" ".join(corpus).lower().split()))
word_to_idx = {w: i for i, w in enumerate(all_words)}
vocab_size = len(all_words)

print(f"Vocabulary ({vocab_size} words): {all_words}")

def one_hot(word, vocab):
    vec = np.zeros(len(vocab), dtype=int)
    if word.lower() in vocab:
        vec[vocab[word.lower()]] = 1
    return vec

words_to_encode = ["food", "good", "pizza", "bad"]
print(f"\n{'Word':<10} Vector")
for w in words_to_encode:
    print(f"{w:<10} {one_hot(w, word_to_idx).tolist()}")

# --- sklearn OHE (for ML pipelines) ---
from sklearn.preprocessing import OneHotEncoder
words = [["cat"], ["dog"], ["fish"], ["bird"], ["cat"]]
encoder = OneHotEncoder(sparse_output=False)
encoded = encoder.fit_transform(words)
print(f"\nsklearn OHE categories: {encoder.categories_}")
print(f"'cat' encoded: {encoded[0]}")
print(f"'dog' encoded: {encoded[1]}")

# --- Disadvantages demonstration ---
cat_vec  = one_hot("food", word_to_idx).astype(float)
good_vec = one_hot("good", word_to_idx).astype(float)
dot = np.dot(cat_vec, good_vec)
print(f"\ncosine_similarity('food','good') = {dot:.1f}  ← all words equally dissimilar")

Bag of Words (BOW)

BOW represents a document as a vector of word counts — ignoring grammar and order. "The food is good" = {food:1, good:1, is:1, the:1}. Simple, effective for text classification. Used in early spam filters (Naive Bayes + BOW).

Preserves
Frequency
Word count in doc
Loses
Word Order
"man bites dog" = "dog bites man"
Variants
Binary BOW
1/0 presence only
How BOW builds the matrix
Documents: S1 = "The food is good" S2 = "The food is bad" S3 = "Pizza is amazing" After preprocessing → vocabulary: [amazing, bad, food, good, pizza] BOW Matrix (rows=docs, cols=words): amazing bad food good pizza S1 (good) 0 0 1 1 0 S2 (bad) 0 1 1 0 0 S3 (pizza) 1 0 0 0 1
08_bag_of_words.pyPython + sklearn
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
import pandas as pd
import numpy as np

corpus = [
    "The food is good",       # label: 1 (positive)
    "The food is bad",        # label: 0 (negative)
    "Pizza is amazing",       # label: 1 (positive)
    "Burger is bad",          # label: 0 (negative)
    "The service was great",  # label: 1 (positive)
]
labels = [1, 0, 1, 0, 1]

# --- Build BOW ---
vectorizer = CountVectorizer(
    lowercase=True,
    stop_words='english',   # auto-remove stopwords
    min_df=1                # min document frequency
)
X = vectorizer.fit_transform(corpus)
feature_names = vectorizer.get_feature_names_out()

# --- Display as DataFrame ---
df = pd.DataFrame(X.toarray(), columns=feature_names)
df.index = [f"S{i+1}" for i in range(len(corpus))]
print("BOW Matrix:")
print(df.to_string())

# --- Binary BOW (just 0/1, ignore frequency) ---
bin_vectorizer = CountVectorizer(binary=True, stop_words='english')
X_bin = bin_vectorizer.fit_transform(corpus)

# --- Sentiment Classifier using BOW + Naive Bayes ---
model = MultinomialNB()
model.fit(X, labels)

test_sentences = ["The pizza is amazing!", "The food was terrible and bad"]
X_test = vectorizer.transform(test_sentences)
predictions = model.predict(X_test)

for sent, pred in zip(test_sentences, predictions):
    print(f"\n'{sent}' → {'POSITIVE ✓' if pred==1 else 'NEGATIVE ✗'}")

TF-IDF — Term Frequency · Inverse Document Frequency

TF-IDF gives higher weight to words that are frequent in a document but rare across all documents. This captures importance better than raw counts — "the" appears everywhere so it gets a low score, but "Python" in a coding article gets a high score.

TF-IDF(t,d) = TF(t,d) × IDF(t)  =  (count(t,d) / total_words(d)) × log(N / df(t))
TF
Word freq in doc
Normalized by doc length
IDF
log(N/df)
Rare words → high IDF
Used In
Search + IR
Core of early Google search
🔍
Early Google Search
TF-IDF was the backbone of document ranking before neural embeddings.
📝
Auto-Summarization
Sentences with highest TF-IDF scoring words become the summary.
🏷️
Keyword Extraction
Top TF-IDF words per document become that document's keywords/tags.
09_tfidf.pyPython + sklearn
from sklearn.feature_extraction.text import TfidfVectorizer
import pandas as pd
import numpy as np

corpus = [
    "The food is good boy",     # S1
    "The food is good girl",    # S2
    "Boy and girl are good",    # S3 — test sentence
]

# --- TF-IDF from sklearn ---
vectorizer = TfidfVectorizer(
    norm='l2',      # normalize vectors (standard)
    smooth_idf=True # prevents division by zero
)
X = vectorizer.fit_transform(corpus)
features = vectorizer.get_feature_names_out()

df = pd.DataFrame(X.toarray().round(3), columns=features)
df.index = ["S1", "S2", "S3"]
print("TF-IDF Matrix:")
print(df.to_string())

# --- Why TF-IDF beats BOW ---
# "good" appears in ALL 3 docs → IDF = log(3/3) ≈ 0 → low weight
# "boy" appears in 2 docs      → IDF = log(3/2) = 0.41
# "girl" appears in 2 docs     → IDF = log(3/2) = 0.41

print("\nIDF values (lower = appears in more documents):")
idf = vectorizer.idf_
for w, v in sorted(zip(features, idf), key=lambda x: x[1]):
    print(f"  {w:<10} IDF={v:.3f}")

# --- Practical: Find most important word per document ---
print("\nTop keyword per document:")
for i, (doc, row) in enumerate(zip(corpus, X.toarray())):
    top_word_idx = np.argmax(row)

N-Grams

N-Grams are contiguous sequences of N words. Unigrams=1 word, Bigrams=2 words, Trigrams=3 words. They capture local word context that BOW misses — "New York" as a bigram has different meaning than "New" + "York" separately.

Single words — BOW

["food is", "is good"]
Word pairs

["food is good"]
3-word sequences

Music/Text Generation

Word Embeddings — Intro

Word embeddings are dense, low-dimensional vectors where semantically similar words are mathematically close. Unlike OHE/BOW, "king" and "queen" are close in embedding space, and king - man + woman ≈ queen. This is the technology behind Google Translate, GPT, and BERT.

OHE Vector
50,000 dim
Sparse, no meaning
Embedding Vector
100–300 dim
Dense, meaningful
Famous Analogy
king−man+woman≈queen
Vector arithmetic works!
The key insight — geometry = meaning
Word Embedding (simplified to 3D) [gender, royalty, age ] king → [-0.95, +0.97, +0.05 ] queen → [+0.97, +0.95, +0.03 ] man → [-0.92, -0.01, +0.10 ] woman → [+0.91, -0.02, +0.09 ] king - man + woman ≈ [-0.95-(-0.92)+0.91, 0.97-0.01+(-0.02), 0.05-0.10+0.09] ≈ [+0.88, +0.94, +0.04] ≈ queen ✓ cosine_similarity("cat", "kitten") = 0.89 ← semantically close ✓ cosine_similarity("cat", "democracy") = 0.12 ← semantically far ✓

Word2Vec — CBOW (Continuous Bag of Words)

CBOW predicts the center (target) word from its surrounding context words. Given ["The", "food", "_", "good"] → predict "is". It averages context embeddings to make the prediction. Faster to train, good for common words.

CBOW: Context Words → [Average Embedding] → Predict Target Word
Input
Context words
Window of ±2 words
Predict
Target word
Center of window
Speed
Fast
Averages context

Word2Vec — SkipGram

SkipGram is the reverse of CBOW: given a center word, predict the surrounding context words. Given "food" → predict ["The", "is", "very", "good"]. Better for rare words. Slower to train but produces richer embeddings.

SkipGram: Target Word → Predict Each Context Word Separately
FeatureCBOWSkipGram
InputContext → predicts targetTarget → predicts context
SpeedFasterSlower
Rare wordsWeakerBetter
Training dataNeeds lessGenerates more pairs
Best forLarge corpus, frequent wordsSmall corpus, rare words

# --- Knowledge base (any text — paste Wikipedia, FAQs, etc.) ---
knowledge_base = """
NLP stands for Natural Language Processing. It is a branch of artificial intelligence 
that helps computers understand, interpret, and generate human language.
Tokenization is the process of splitting text into individual words or sentences.
Stemming reduces words to their root form by removing suffixes.
Lemmatization converts words to their base dictionary form using vocabulary and grammar rules.
Stopwords are common words like the, is, a that carry little meaning.
Bag of Words represents text as word frequency vectors.
TF-IDF stands for Term Frequency Inverse Document Frequency. It weighs words by importance.
Word2Vec creates dense vector embeddings where similar words are mathematically close.
Named Entity Recognition identifies persons, places, organizations in text.
Sentiment Analysis classifies text as positive, negative, or neutral.
"""

# --- Preprocessing pipeline using your NLP knowledge ---
lemmatizer = WordNetLemmatizer()
stop_words = set(nltk.corpus.stopwords.words('english'))

def preprocess(text):
    tokens = word_tokenize(text.lower())
    tokens = [t for t in tokens if t.isalpha() and t not in stop_words]
    tokens = [lemmatizer.lemmatize(t) for t in tokens]
    return " ".join(tokens)

# --- Build sentence corpus ---
sentences = sent_tokenize(knowledge_base.strip())
processed_sentences = [preprocess(s) for s in sentences]

# --- TF-IDF retrieval ---
vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(processed_sentences)

def get_response(user_input):
    """Find the most relevant sentence from knowledge base."""
    processed_input = preprocess(user_input)
    input_vec = vectorizer.transform([processed_input])
    similarities = cosine_similarity(input_vec, X).flatten()
    best_idx = np.argmax(similarities)
    best_score = similarities[best_idx]
    
    if best_score < 0.1:
        return "I'm sorry, I don't have information about that. Can you rephrase?"
    return sentences[best_idx].strip()
